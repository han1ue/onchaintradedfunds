# Security and risk

Status: pre-mainnet, unaudited, experimental. No deployment is approved. This document describes
the current immutable-bootstrap architecture; it is not an audit, warranty, or investment advice.

## Security boundary

`OTFFactory` is permissionless once its entry/exit router is configured. `createVault` makes
`msg.sender` the creator, deploys a nondeterministic EIP-1167 clone with `Clones.clone`, and commits
the ordered constituents and creator-supplied `bootstrapBasketUnitsPerOTF`. Creation does not move
constituents into the vault.

The factory and vault deliberately do not receive or validate prices, market caps, percentage
weights, or the fixed `$1` initial basket target. The application uses these values offchain to calculate raw bootstrap
units and displays the integer-rounding result before submission. Users must treat that calculation
and its data source as economic inputs chosen by the creator, not as authenticated onchain facts.
The `$1` target is not a peg or guaranteed market price.

`Market-cap weighted` and `Modified market-cap weighted` describe the initialization calculation,
not an ongoing onchain rebalance. Market-cap defaults, final percentages, multipliers, timestamps,
and methodology labels are informational application metadata. If that creation record is missing,
the interface does not reconstruct it from current balances.

There is no runtime NAV, price oracle, Chainlink feed, TWAP, keeper, market-data refresh, or
automatic rebalance. Prices and composition can drift without any contract response.

## Main risks and mitigations

### Creator-selected bootstrap basket

A creator can submit inaccurate, stale, manipulated, or economically unsuitable bootstrap units.
The contract validates array shape, unique contract constituents, the basket-size cap, and nonzero
units, but it cannot prove that a unit corresponds to any dollar target or percentage. The UI's
current prices, market caps, percentages, realized allocation, fixed `$1` target, and source timestamp
must remain visible application metadata. Asset-source policy and monitoring require independent
production review.

The creator and one-time router configurator remain trust roles. A creator can irreversibly shut
down a sound vault. Any caller can shut down a vault when a readable constituent balance proves a
backing deficit; a failed read or donation is not proof.

### Bootstrap, supply floor, and rounding

The first mint after any zero-supply state requires at least `1e18` shares and uses ceiling-rounded
immutable bootstrap units. Later mints use ceiling-rounded current accounted balances per share.
Normal redemption uses floor rounding, except full redemption returns every accounted balance
exactly. After fee accrual, a partial normal redemption cannot leave supply between 1 and
`1e18 - 1`; `ResidualSupplyTooSmall` protects the normal-settlement invariant
`totalSupply == 0 || totalSupply >= 1e18`.

Emergency redemption intentionally has no residual-supply floor. Following shutdown, preserving a
holder's ability to exit is more important than keeping the normal settlement invariant.

### Basket accounting and tokens

`accountedBalance` is an internal ledger. Direct tracked-token donations increase actual balance
without increasing the ledger or creating a donor claim. Normal settlement fails closed when
actual backing is below accounted backing. After shutdown, public in-kind emergency redemption
pays at most `min(actual, accounted)` per asset, excludes donation excess, and handles deficits.

Transfers require exact sender and receiver balance deltas. Fee-on-transfer, sender-taxed,
rebasing, callback-mutating, and otherwise non-exact ERC-20s are unsupported. The protocol cannot
make proxy implementations, decimals, or future token behavior immutable; production asset policy
must exclude unsuitable tokens even if an application labels them verified.

### Expense dilution and protocol shares

The creator expense is share inflation, not an asset transfer. Its ratio and beneficiary are fixed
at initialization. Fee growth is lazy and cadence-independent. The factory supplies one immutable
protocol fee share for every vault; there is no constituent- or allocation-based adjustment.
Protocol shares are held by `FeeCollector`, whose treasury is the only claimant.

### Router, pools, and external liquidity

`OTFEntryExitRouter` authenticates typed Uniswap V3 paths against one immutable factory/router
pair. It bounds route shape, checks deadlines and minimums, verifies exact observed deltas, clears
temporary approvals, restricts recipients and refunds to the sender, blocks reentrancy, and rolls
back atomically. Neither contract nor app promises global quote optimality.

The configured venue must implement SwapRouter02's four-field `exactInput` ABI and share the
expected V3 pool bytecode family. Production needs funded direct-buy, direct-sell, and multihop fork
tests against exact deployment addresses. Pool fees belong to LPs; creators promise neither
liquidity nor execution price.

If all usable routes disappear while backing is sound, only the creator can activate emergency
in-kind redemption. A lost or hostile creator can therefore strand holders until a backing deficit
becomes provable. This is an explicit liveness limitation.

## Explicit limitations and unresolved blockers

- No formal audit or independent economic review has been completed.
- Creator-selected bootstrap units and offchain asset data remain economic trust inputs.
- New production deployments, governance/key management, monitoring, and incident procedures are
  unresolved.
- Production quote services, mainnet OTF addresses, and funded venue fork evidence are unresolved.
- Malicious, rebasing, fee-on-transfer, and mutable tokens remain unsupported.
- Sound-vault emergency exit still depends on the creator.
- No share is promised to track a dollar, percentage target, or current index.
- `launch/` is a separate prelaunch competition and is outside this threat model.

Report suspected vulnerabilities privately to the repository maintainers. Include the affected
contract, chain/commit, reproduction steps, impact, and whether funds or keys may be at risk. Never
include seed phrases or private keys.
