# Protocol security specification

The keywords MUST, MUST NOT, and SHOULD describe required v2 behavior.

## OTF supply

`OTFToken` MUST mint exactly `1,000,000,000 ether` in its constructor and MUST expose no later mint
path. `MAX_SUPPLY` MUST remain fixed while `totalSupply()` MUST fall when a holder burns owned or
properly allowed tokens. Deployment MUST allocate exactly 100 million to team vesting, 200 million
to the launch manager, and 700 million to rewards, leaving the deployer with zero OTF.

## Canonical launch

The launch manager MUST create one OTF/WETH V4 pool with static fee 0 and tick spacing 1. It MUST use
`MAX_SUPPLY`, not live supply, to construct deterministic start and final ticks. Bootstrap MUST hold
150 million one-sided OTF and no supplied WETH. The reserved 50 million OTF MUST be used only for
post-graduation permanent liquidity. Its hook address MUST encode exactly `beforeInitialize` and
`afterSwap`; every third-party attempt to initialize the canonical pool MUST revert, including while
the predicted CREATE2 launch-manager address has no deployed code.

Only reaching or crossing the final bootstrap tick MAY mark graduation ready. Finalization MUST be
permissionless, settle the completed bootstrap position, combine its WETH proceeds with up to the
reserve, and mint effectively full-range liquidity. No callable path may remove, reprice, rebalance,
migrate, or replace that principal. Dust MUST remain locked and MUST NOT block graduation.

## Team vesting

Live FDV MUST use canonical V4 spot state, the configured ETH/USD answer, and the current token
`totalSupply()`. Both currency orderings MUST produce the same economic price. The oracle answer MUST
be positive, no older than `maxOracleAge`, and not from the future. Checkpoints MUST round down to a
completed $1 million milestone, unlock 10 million OTF per milestone through $10 million, and never
decrease. Claims MUST go only to the fixed beneficiary and MUST NOT exceed unlocked less claimed.

## Fund fees and accounted OTF

Annual creator expense, mint, and redeem rates MUST be immutable and capped at 1,000, 200, and 100
bps. Mint fees MUST apply to direct and routed minting. Redeem fees MUST apply to direct, routed, and
normal in-kind redemption. Shutdown and final emergency exits MUST charge no redeem fee. Preview and
execution functions MUST use identical integer arithmetic.

Every operation that changes accounted OTF MUST checkpoint accrued annual fees first. Direct token
donations MUST NOT change accounted balance or fee benefit. The creator share MUST be:

```text
5000 bps + floor(4000 bps × sqrt(min(accounted OTF, 10m OTF) / 10m OTF))
```

The creator share MUST remain between 5,000 and 9,000 bps. Mint and redeem creator fee shares MUST
round down; annual expense splitting MUST carry its fractional remainder across checkpoints. All
remaining collected fee shares MUST go to the buyback collector. No fund-owned constituent OTF may
be transferred to the collector merely because it is OTF.

## Native entry and exit

`OTFEntryExitRouter` MUST store a nonzero immutable canonical WETH. Native mint MUST require nonzero
`amountIn` and exact `msg.value == amountIn`; every ERC-20 endpoint MUST reject native value. It MUST
wrap exactly the accepted ETH and use only WETH in basket planning, vault calls, and adapter legs.
Transient WETH refunds MUST be unwrapped and returned as ETH while other constituent refunds remain
ERC-20 transfers.

Native redemption MUST route to canonical WETH, enforce the aggregate WETH minimum, unwrap exactly
the transient output, and send exactly that ETH to the caller. Native sends MUST be checked and revert
atomically on rejection. The router MUST accept callback ETH only from canonical WETH, keep every
wrap, unwrap, send, and refund inside the reentrancy guard, clear temporary approvals, and preserve
all pre-existing or forcibly sent ETH and WETH. Native sentinels, the zero address, and native ETH
MUST NOT reach a vault, `SwapLeg`, or adapter.

## Buyback collector

Only the configured route executor MAY submit buyback routes. Every leg MUST name exact input and
output tokens, an adapter currently approved by the entry/exit router, positive minimum output, and
typed adapter data. The operation MUST enforce a deadline, minimum aggregate WETH, observed WETH
delta, minimum final OTF, and observed OTF delta.

The WETH-to-OTF swap MUST use only the immutable canonical V4 pool key. All OTF acquired by that
execution MUST be burned before success. The collector MUST NOT expose arbitrary calls, token
withdrawals, rescue functions, or configurable final routes.

## Cumulative rewards

Only the configured publisher MAY set a root. A new root MUST be active immediately. Leaves MUST
commit to chain ID, distributor, user, and cumulative entitlement using the documented standard-tree
encoding. Anyone MAY submit a proof, but tokens MUST go to the committed user. A claim MUST equal the
proven cumulative entitlement less stored prior claims. Invalid proofs, double claims, and decreasing
cumulative values MUST revert. The publisher MUST have no rewards-principal withdrawal path.

## Deployment and verification

All production dependencies MUST be explicit. Production MUST use official Uniswap V4 deployments.
Testnet mirror dependencies MUST match operator-supplied expected bytecode hashes before deployment.
Generated ABIs, frontend configuration, tests, and documentation MUST describe only v2. Earlier
testnet contracts MUST NOT be treated as compatible.
