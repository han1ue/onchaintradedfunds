# Deployment addresses

The OTF token-economics v2 architecture requires a fresh deployment. No production or replacement
testnet protocol address is recorded until that deployment is performed and verified.

## Robinhood Chain Mainnet

**Chain ID:** `4663` <br />
**Explorer:** [robinhoodchain.blockscout.com](https://robinhoodchain.blockscout.com/) <br />
**Status:** Not deployed

Before a production deployment, operators must supply explicit addresses for WETH, the existing
Uniswap V3 factory and SwapRouter02, the official Uniswap V4 PoolManager, StateView,
PositionManager, Universal Router, Permit2, and the selected ETH/USD oracle. The protocol multisig,
team beneficiary, and authorized route executor must also be chosen. The repository does not invent
or default these values.

## Robinhood Chain Testnet

**Chain ID:** `46630` <br />
**Explorer:** [explorer.testnet.chain.robinhood.com](https://explorer.testnet.chain.robinhood.com/) <br />
**Status:** Redeployment required

The old generic-adapter deployment and its fee collector are intentionally unsupported. The
application therefore disables protocol reads and transactions instead of falling back to stale
addresses.

The deployment script uses the repository's documented Robinhood Testnet V4 mirror addresses for
PoolManager, StateView, Universal Router, and Permit2. PositionManager is an explicit operator input.
Expected bytecode hashes for all five dependencies are mandatory and checked before any protocol
contract is deployed. Testnet ETH/USD uses `FakeETHUSDOracle`, fixed at exactly `$2,000`.

After a successful deployment, `app/src/config/robinhood-testnet.json` records:

- OTF token, launch manager, team vesting, buyback collector, Merkle distributor;
- vault implementation, factory, entry/exit router, and V3/V4 adapters;
- verified periphery dependencies and code hashes;
- adapter approvals, initialization transactions, and exact initial allocations.

Factory-created fund vault addresses remain dynamic and are discovered onchain.
